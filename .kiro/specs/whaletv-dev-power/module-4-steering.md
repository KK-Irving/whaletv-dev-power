# Skill: 模块 4 - Steering 工作流文件

## 适用范围

编写 `steering/` 目录下的 6 个工作流指南文件。

## Steering 文件通用结构

每个 Steering 文件遵循以下结构：

```markdown
# [工作流名称]

## 触发场景
描述何时激活此工作流

## 前置条件
列出执行前必须满足的条件

## 工作流步骤

### 步骤 1: [步骤名称]
**AI 动作**: 具体执行什么
**预期输出**: 执行后应产出什么
**错误处理**: 失败时如何应对

### 步骤 2: [步骤名称]
...

### 👤 用户确认点: [确认内容]
**展示内容**: 向用户展示什么
**等待条件**: 用户需要做什么才能继续

## 输出格式
定义最终产出物的结构

## 错误恢复
定义全局错误处理策略
```

## 编写规范

1. **语言**：全部使用中文
2. **步骤编号**：使用 ① ② ③ 等圆圈数字
3. **用户确认点**：使用 👤 emoji 标记，必须明确说明"等待用户确认后才继续"
4. **工具引用**：使用反引号包裹工具名，如 `get_issue`、`search_code`
5. **命令引用**：使用代码块包裹命令，如 `git add -p`
6. **条件分支**：使用 "IF...THEN..." 格式
7. **格式模板**：使用代码块展示固定格式

## 各文件要点

### pr-cr-workflow.md
- 9 个步骤严格有序
- 2 个用户确认点（diff 确认、push 确认）
- Commit Message 格式必须完整定义
- 必须引用 `git add -p` 进行 hunk 暂存

### cherry-pick-workflow.md
- 表格展示 CP 计划
- 结果分三类：成功/跳过/冲突
- MP 分支发现逻辑（`_mp` 后缀）
- 自动更新 Zmind 评论

### bug-analysis-workflow.md
- 日志文件识别规则（文件名 + 扩展名）
- 日志解析三要素（异常栈、时间事件、重复关键字）
- 代码定位优先级（git grep → OpenGrok）
- 报告格式四部分（现象、关键 Log、根因定位、修复建议）

### gerrit-workflow.md
- gerritpush 命令 + Reviewer
- 轮询逻辑（3 次，15 秒间隔）
- 评论处理（采纳/不采纳 + resolved）

### local-code-guide.md
- 搜索优先级三层（git grep → 读文件 → OpenGrok）
- git grep 用法示例
- 目录结构说明
- 跨代码库提示
- 非源码目录检测

### safety-rules.md
- 三层防护体系说明
- 规则约束列表
- Hook 拦截规则引用
- 人工确认场景列表
- 拦截信息格式模板

## 关键约束

- 不要在 Steering 文件中硬编码 API Key 或 URL
- 工具名必须与 MCP Server 中注册的名称完全一致
- 每个确认点必须明确说明"等待用户输入明确的确认指令"
- 错误处理必须包含"报告错误 + 等待用户指示"两步
