# Gerrit 操作工作流

## 触发场景

代码推送和 Gerrit-AI 评论处理（如"推送代码到 Gerrit"、"处理 Gerrit 评论"）

## 前置条件

- 代码已 commit（`git status` 显示 working tree clean 或仅有已暂存的变更已提交）
- `gerritpush` 命令可用（已配置在系统 PATH 中）
- 当前目录为 AOSP 源码目录（包含 `.repo` 或典型子目录如 `frameworks/`、`packages/`）

## 工作流步骤

### ① 推送代码

**AI 动作**: 使用 `gerritpush` 命令推送代码到 Gerrit，根据用户指定或项目配置的 Reviewer 列表自动添加 Reviewer
```bash
gerritpush
```
**预期输出**: 代码成功推送到 Gerrit，获得 Change 链接
**错误处理**: IF `gerritpush` 执行失败（如权限不足、网络不可达、分支冲突），THEN 报告错误信息，等待用户指示是否重试或终止

### ② 轮询等待 Gerrit-AI 评论

**AI 动作**: 推送完成后，轮询等待 Gerrit-AI 生成评论，最多轮询 3 次，每次间隔 15 秒

**轮询逻辑**:
- 第 1 次轮询：推送完成后等待 15 秒，查询评论
- 第 2 次轮询：IF 第 1 次无评论，THEN 再等待 15 秒，查询评论
- 第 3 次轮询：IF 第 2 次无评论，THEN 再等待 15 秒，查询评论

**预期输出**: 获取到 Gerrit-AI 生成的评论列表，或确认 3 次轮询后无评论
**错误处理**: IF 轮询过程中 Gerrit API 调用失败，THEN 报告错误信息，等待用户指示

**关键约束**:
- 轮询间隔固定 15 秒
- 最多轮询 3 次

### ③ 评论处理

**AI 动作**: 根据轮询结果进行分支处理

---

**IF 3 次轮询后无评论**:

通知用户当前无 Gerrit-AI 评论，结束流程。

输出示例：
```
Gerrit-AI 暂无评论（已轮询 3 次，间隔 15 秒），流程结束。
如需后续处理评论，请稍后再次触发。
```

---

**IF 有评论**:

逐条分析 Gerrit-AI 评论，结合代码变更上下文判断是否采纳：

#### 采纳评论

1. **修复代码**: 根据评论建议修改对应代码
2. **回复修复说明**: 在 Gerrit 上回复该评论，说明已采纳并描述修复内容
3. **标记 resolved**: 将该评论标记为 resolved

回复格式示例：
```
已采纳，修复说明：[具体修复内容描述]
```

#### 不采纳评论

1. **回复不采纳理由**: 在 Gerrit 上回复该评论，说明不采纳的具体理由
2. **标记 resolved**: 将该评论标记为 resolved

回复格式示例：
```
不采纳，理由：[具体不采纳原因]
```

**预期输出**: 所有 Gerrit-AI 评论已逐条处理完毕，每条评论都有回复且标记为 resolved
**错误处理**: IF 无法判断某条评论是否应采纳，THEN 向用户展示评论内容并请求指示

## 错误恢复

任一步骤执行失败时：

1. **报告失败**: 明确告知用户失败发生在哪个步骤，以及具体的错误信息
2. **等待指示**: 等待用户决定是重试当前步骤、跳过、还是终止整个流程
3. **不自动重试**: 不在未经用户确认的情况下自动重试失败的操作

## 关键约束

| 约束 | 说明 |
|------|------|
| 每条评论必须标记 resolved | 无论采纳还是不采纳，回复后都必须将评论标记为 resolved |
| 轮询间隔固定 15 秒 | 每次轮询之间等待 15 秒，不可缩短或延长 |
| 最多轮询 3 次 | 超过 3 次仍无评论则通知用户并结束，不继续等待 |
| Reviewer 自动添加 | 使用 `gerritpush` 推送时根据用户指定或项目配置自动添加 Reviewer |
